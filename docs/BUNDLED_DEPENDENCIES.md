# Bundled Windows dependencies

LensioStudio runs asInvoker. Normal camera reception, streaming, USB tools and updates run without administrator rights. The separate `--install-virtual-camera` entry point exits before UI, WebView2 and network initialization. It accepts no input paths or commands and refuses unelevated callers.

The installer extracts only allowlisted embedded payloads, checks decompressed length and SHA-256, rejects redirected/reparse-point paths, and writes camera files into Program Files/Lensio/VirtualCamera/1.0.1 with administrator/SYSTEM write access and Users read/execute access. It invokes only the Windows System32/SysWOW64 regsvr32 tools and verifies both registrations. The camera installer adds no service, scheduled task, remote desktop access, firewall exception or startup entry. Microsoft WebView2 manages its own updates separately. The tray menu has Install / repair virtual camera for retrying after cancellation.

## Provenance and licensing

- Lensio virtual camera 1.0.1: compiled x64/x86 from adapted OBS 32.1.0 and pinned libdshowcapture sources in `LensioStudio/native`. It has its own CLSID, `LensioVirtualCamVideo` queue, DLL names and metadata file; OBS Virtual Camera remains independently registered and receives its own stream. `Build-VirtualCamera.ps1` builds the modules and records their sizes/SHA-256 in the embedded manifest. The modules are not code-signed. Their static MSVC runtime avoids requiring a separate runtime installation. The complete modified module source and build scripts are attached as `Lensio-VirtualCamera-source.zip`; upstream/license provenance is documented in `LensioStudio/native/README.md`.
- OBS Studio 32.1.0 official signed camera modules remain embedded only for migration: when the old OBS CLSID points exactly to Lensio's protected legacy directory, setup restores that original class/name using verified official payloads. A separate existing OBS registration is not replaced. Known old Lensio branding/alias entries are corrected only after checking their identity. The matching official OBS source and GPL text remain release assets.
- Android platform-tools 36.0.2: official Google archive. Only adb.exe, AdbWinApi.dll and AdbWinUsbApi.dll are embedded, with the full upstream notices in ANDROID-PLATFORM-TOOLS-NOTICES.txt and the EXE. ADB runs as the user, and Android requires USB debugging authorization on the phone. No device commands can be supplied to the elevated helper.
- Microsoft WebView2: pinned SDK and signed official Evergreen bootstrapper. The bootstrapper runs as the user only after confirmation, and downloads the Evergreen Runtime from Microsoft if missing. Bundling the entire browser runtime would add hundreds of megabytes; native Android cameras remain usable if this optional installation is declined. WebView2's runtime license/update behavior remains Microsoft's.

All payloads are fetched only at build time from official hosts. No camera module is downloaded or taken from adjacent editable scripts during elevated setup. The program explicitly excludes the current directory and PATH from native DLL search. Embedded DLLs depend on Windows system libraries; no Visual C++ redistributable is needed for the virtual camera. The modified Lensio camera modules and LensioStudio.exe are unsigned; Windows may show Unknown publisher for setup. Only the legacy official OBS payloads and the Microsoft bootstrapper retain their upstream signatures.

## Network and checks

The browser-to-native video bridge listens on loopback with a random session token, bounded requests, origin validation and a restrictive CSP. Native phone sockets retain bounded frames, connection counts and timeouts. A bounded LAN identity endpoint is retained only for camera discovery. The APK update server, download endpoints and remote phone-update commands have been removed. Native Android streaming is intended for a trusted local network; it does not add encryption or authenticated pairing to the legacy LAN protocol. Use a trusted Wi-Fi or authorized USB connection. Both clients obtain updates independently over GitHub HTTPS and require exact release URLs, SHA-256 digests and matching streamed byte counts. The Windows Setup rechecks its hash, waits for the studio to close, replaces only LensioStudio.exe in the current folder and starts the app with normal user rights. The previous PowerShell update helper is no longer generated. Android additionally enforces package/signature compatibility.

The automated setup tests verify embedded hashes/lengths, path allowlisting, non-admin helper rejection, standalone ADB execution, HTTP bounds, QR/web reception and desktop regressions. Windows installation and DirectShow capture are tested separately. These checks reduce known risks; they are not a claim that the application has no vulnerabilities or a substitute for an independent security audit.
