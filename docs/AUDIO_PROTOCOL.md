# Native PC audio sharing

LensioStudio captures the Windows default playback endpoint with shared-mode WASAPI loopback. Windows converts the endpoint mix to 48 kHz, stereo, signed PCM16 using its high-quality sample-rate conversion flags. The capture worker owns initialization, reads and COM cleanup. Endpoint failures release the old client and retry after a bounded delay. Stop requests shutdown and waits for the worker; it never releases an interface while another thread is reading from it.

Each protocol frame is 968 bytes: an eight-byte header followed by 960 PCM bytes (240 stereo samples, five milliseconds). The header starts with ASCII `SA` and a big-endian 16-bit sequence number. Existing TCP/UDP transport and silence suppression remain in use. Android tries TCP first and can fall back to UDP for Wi-Fi connections.

TCP reads retain partial frame offsets across socket timeouts. UDP receives reset the reusable datagram's capacity before each packet, so a short `CONNECTED_OK` or `PONG` reply cannot truncate the following PCM frame. The jitter buffer and playback path receive complete validated frames only. Partial AudioTrack writes complete the remaining bytes; failed or zero-progress writes cause bounded playback recreation instead of spinning. Only the playback worker releases its AudioTrack. Reconnecting to a different PC address replaces the receiver, and an inactive receiver can be started again.

Camera-catalog diagnostics include audio running state, received and played frame counts, playback restart count, bounded error text, buffered milliseconds and underruns. They contain no recorded audio. Played frames include silence generated by the jitter buffer; underruns during suppressed silent transport are not proof of audible loss. These diagnostics are local device information, not external telemetry.

`AudioPacketIOTest` exercises short UDP replies, partial TCP input with a timeout, cancellation, partial writes and failed playback writes. The device-only `AudioUdpDeviceTest` interleaves short replies with 240 PCM frames and verifies reception and AudioTrack playback without recreation. `tests/AudioCaptureSmoke.cs` is an optional Windows hardware check: it plays a quiet synthetic tone, captures the actual loopback signal, verifies the wire format and repeats start/stop six times. It is intentionally excluded from hosted CI, which may have no playback endpoint. These checks do not establish acoustic quality on every phone or every Windows audio driver.
